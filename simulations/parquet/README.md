# Parquet Analytical Trajectory Storage (`simulations/parquet`)

This directory contains columnar Apache Parquet (`.parquet`) files generated by the high-throughput .NET 10 trajectory ingestion pipeline in `NanoWeaverHrt`.

---

## 1. Directory Purpose & Architecture

Molecular dynamics simulations of DNA origami nanostructures and steroid payloads generate hundreds of thousands of coordinate frames. While raw trajectory formats (`.xyz`, `.dump`, `.dcd`) are ideal for sequential frame-by-frame streaming, analytical queries—such as computing Root-Mean-Square Deviation (RMSD), inter-domain radial displacement, and steroid leakage rates—require columnar layouts for zero-copy analytics.

The .NET 10 SIMD parsing pipeline parses raw trajectory streams from `simulations/shared-data/` without intermediate heap allocations, aggregates coordinate windows, and writes compressed columnar Parquet files to this directory.

### Storage Characteristics
- **Format**: Apache Parquet (v2.6+).
- **Compression**: Snappy (`SNAPPY`), optimizing decompression bandwidth on modern multi-core SIMD architectures.
- **Encoding**: Dictionary encoding for repeated categorical identifiers (e.g., `atom_type`, `target_region`).
- **Container Mount**: Mounted read-write to `/workspace/parquet:rw` in the `trajectory-parser` service, and read-only to analytical PostgreSQL/DuckDB environments.

## 2. Parquet Schema Definition

Each row in the trajectory Parquet files models a discrete particle or atom observation at a specific simulation timestep:

| Column Name | Physical Data Type | Logical Type | Units | Description |
| :--- | :--- | :--- | :--- | :--- |
| `timestep` | `INT64` | Timestamp / Step | Index | Simulation integration timestep counter. |
| `atom_id` | `INT32` | Integer ID | Dimensionless | Unique global index of the atom or nucleotide bead. |
| `atom_type` | `BYTE_ARRAY` | UTF8 String | Dimensionless | Element or bead identifier (e.g., `C`, `N`, `P`, `Ade`, `Thy`, `Gua`, `Cyt`). |
| `x` | `FLOAT` | 32-bit Float | Ångström (Å) | Cartesian position along the X-axis. |
| `y` | `FLOAT` | 32-bit Float | Ångström (Å) | Cartesian position along the Y-axis. |
| `z` | `FLOAT` | 32-bit Float | Ångström (Å) | Cartesian position along the Z-axis. |
| `vx` | `FLOAT` | 32-bit Float | Å / fs | Instantaneous velocity vector along the X-axis. |
| `vy` | `FLOAT` | 32-bit Float | Å / fs | Instantaneous velocity vector along the Y-axis. |
| `vz` | `FLOAT` | 32-bit Float | Å / fs | Instantaneous velocity vector along the Z-axis. |
| `target_region` | `BYTE_ARRAY` | UTF8 String | Label | Structural functional domain (e.g., `nanocage_core`, `aptamer_latch`, `steroid_payload`, `solvent_shell`). |
| `distance_from_center`| `FLOAT` | 32-bit Float | Ångström (Å) | Radial Euclidean distance from the nanocarrier centroid. |

## 3. Querying with pg_duckdb

When the auxiliary database infrastructure is running (`docker compose -f docker-compose.yml -f docker-compose.infra.yml up -d`), PostgreSQL on port `5432` integrates the embedded DuckDB execution engine (`pg_duckdb`), enabling SQL queries across raw Parquet files without database ingestion overhead.

### Trajectory Exploration Queries

#### A. Basic Inspection and Row Counts
```sql
-- Count total atom observations across all parquet partitions
SELECT count(*) AS total_observations
FROM read_parquet('/workspace/parquet/*.parquet');
```

#### B. Mean Radial Displacement by Functional Domain
Verifies structural integrity of the nanocage core versus the flexible aptamer arms:
```sql
SELECT
    target_region,
    COUNT(DISTINCT atom_id) AS distinct_atoms,
    AVG(distance_from_center) AS avg_radial_distance_angstroms,
    STDDEV(distance_from_center) AS radial_stddev
FROM read_parquet('/workspace/parquet/*.parquet')
GROUP BY target_region
ORDER BY avg_radial_distance_angstroms DESC;
```

#### C. Steroid Payload Leakage Analysis
Identifies whether hormone molecules (17β-estradiol or testosterone) have escaped beyond the nanocarrier boundary radius (e.g., 45.0 Å):
```sql
SELECT
    timestep,
    atom_id,
    target_region,
    distance_from_center
FROM read_parquet('/workspace/parquet/*.parquet')
WHERE target_region = 'steroid_payload'
  AND distance_from_center > 45.0
ORDER BY timestep ASC;
```

#### D. Time-Series Coordinate RMSD (Root-Mean-Square Deviation)
Evaluates thermal equilibrium stability under human physiological body temperature (37.0°C / 310.15 K):
```sql
WITH reference_frame AS (
    SELECT atom_id, x AS ref_x, y AS ref_y, z AS ref_z
    FROM read_parquet('/workspace/parquet/*.parquet')
    WHERE timestep = 0 AND target_region = 'nanocage_core'
),
current_frames AS (
    SELECT timestep, atom_id, x, y, z
    FROM read_parquet('/workspace/parquet/*.parquet')
    WHERE target_region = 'nanocage_core'
)
SELECT
    c.timestep,
    SQRT(AVG(POW(c.x - r.ref_x, 2) + POW(c.y - r.ref_y, 2) + POW(c.z - r.ref_z, 2))) AS rmsd_angstroms
FROM current_frames c
JOIN reference_frame r ON c.atom_id = r.atom_id
GROUP BY c.timestep
ORDER BY c.timestep ASC;
```

## 4. Maintenance and File Hygiene

- **Sample Datasets**: Small verification fixtures (`dna_sample.parquet`, `dna_nanotube_sample.parquet`) are version-controlled for automated regression testing.
- **Large Production Runs**: Large production `.parquet` files generated during multi-microsecond simulation runs should be archived to dedicated object storage or exported via `/api/datasets/export`.
- **Git Retention**: Production parquet outputs exceeding 50 MB should not be checked into git.
