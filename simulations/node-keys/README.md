# Sovereign Node Keys Directory (`simulations/node-keys`)

This directory persists the cryptographic identity, digital signature, and data-protection keys generated by the sovereign .NET 10 microservice node (`NanoWeaverHrt`).

---

## 1. Directory Purpose & Security Invariants

All secret key material in this directory is generated automatically upon the node's first boot using cryptographically secure random number generators (`RandomNumberGenerator`).

### Mandatory File Protection Rules
- **Access Permissions**: Every secret key file is created with strict POSIX mode `0600` (`-rw-------`), granting read/write access exclusively to the process owner (UID:GID `1000:1000`).
- **Version Control Exclusion**: All `*.key` files are explicitly excluded via `.gitignore` and must **never** be committed to any git remote.
- **Dedicated Container Mount**: In `docker-compose.yml`, this directory is mounted to `/workspace/node-keys:rw` on the `trajectory-parser` container only. It is **inaccessible** to the `simulation` engine container to prevent process cross-contamination.

---

## 2. Key Inventory

| File Name | Size | Algorithm / Purpose | Description & Recovery Impact |
| :--- | :--- | :--- | :--- |
| `token_signing.key` | 32 bytes | HMAC-SHA256 (256-bit) | Signs session tokens and `weaver_session` cookies. Losing this key invalidates active user sessions upon restart, requiring users to authenticate again. |
| `phi_master.key` | 32 bytes | AES-256-GCM (256-bit KEK) | Node-level master key used by `ProfileDataProtector` to encrypt patient Protected Health Information (PHI) and DNA regimen payloads at rest. **Critical:** Losing this key renders existing encrypted patient profiles and DNA records unrecoverable. |
| `node_signing_mldsa65.key` | 32 bytes | NIST FIPS 204 (ML-DSA-65 Seed) | Persisted 32-byte seed used to derive this node's post-quantum signature keypair for tamper-evident FDA 21 CFR Part 11 audit ledger sealing (`weaver_audit_ledger`). |
| `dataset_signing_ed25519.key` | 32 bytes | RFC 8032 (Ed25519 Seed) | Persisted 32-byte seed used to sign exported dataset manifests (`.manifest.json`), enabling remote peer nodes to verify dataset provenance and authenticity. |

---

## 3. Backup and Disaster Recovery

Operators deploying sovereign nodes should include this directory in encrypted off-site backups:
```bash
# Example encrypted backup of node secrets
tar -czf - simulations/node-keys/ | gpg --symmetric --cipher-algo AES256 > node-keys-backup-$(date +%Y%m%d).tar.gz.gpg
```

Do not regenerate or overwrite existing keys on a production node unless intentionally conducting a full cryptographic rotation.
