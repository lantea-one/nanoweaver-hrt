# Simulation Dataset Exports Directory (`simulations/exports`)

This directory stores cryptographically packaged, self-contained dataset export bundles generated by the sovereign Web UI or the dataset export API (`/api/datasets/export`).

---

## 1. Directory Purpose & Export Architecture

The dataset export subsystem enables sovereign nodes to bundle raw trajectories, parsed columnar metrics, and simulation topology manifests into portable, tamper-evident archives for peer-to-peer distribution and collaborative research.

### Paired Artifact Structure
Each exported dataset produces a paired set of artifacts:
1. **Compressed Archive (`<dataset-name>.tar.gz` or `.enc.tar.gz`)**:
   - A POSIX gzip-compressed TAR archive containing the simulation coordinate files, topology configuration, and optional Parquet columnar slices.
   - If encrypted for peer delivery, the payload is protected with AES-256-GCM using the peer node's registered public key.
2. **Cryptographic Provenance Manifest (`<dataset-name>.manifest.json` or `.manifest.pqc.json`)**:
   - A canonical JSON manifest detailing the archive metadata, SHA-256 digest, creation timestamp, schema version, and file inventory.
   - Digitally signed with the originating node's persistent Ed25519 dataset signing key (`dataset_signing_ed25519.key`).

---

## 2. Manifest Schema & Digital Signatures

A standard manifest includes:
- `manifestVersion`: Schema version (`2`).
- `datasetName`: Human-readable identifier.
- `generatedAtUtc`: ISO 8601 UTC timestamp.
- `archiveSha256`: SHA-256 hash of the `.tar.gz` archive file.
- `signingKeyId`: Hex-encoded SHA-256 fingerprint of the originating node's public key.
- `signatureAlgorithm`: Asymmetric algorithm (`Ed25519`).
- `signature`: Base64-encoded digital signature over canonicalized manifest fields.

### Peer Import Verification
When importing datasets (`POST /api/datasets/import`):
1. The importing node computes the SHA-256 hash of the incoming archive and compares it with `archiveSha256`.
2. The manifest signature is verified against this node's own dataset signing key or known peer public keys stored in the database registry (`weaver_peer_keys`).
3. If `Peer:RequireSignedDatasets` is enabled (`true`), unsigned dataset archives or manifests from unknown peers are rejected with an RFC 7807 problem details response.

---

## 3. Storage and Repository Invariants

- **Git Exclusion**: Generated export archives and manifests (`*.tar.gz`, `*.enc.tar.gz`, `*.manifest.json`, `*.manifest.pqc.json`) are ignored by `.gitignore` to prevent repository bloat.
- **Volume Mount**: Mounted to `/workspace/exports:rw` in both `weaver-simulation` and `weaver-parser` containers.
- **Preservation**: The `.gitkeep` file ensures this directory structure remains tracked in version control across clean repository checkouts.
